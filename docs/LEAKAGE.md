# Label leakage through the report text

> The short version: MIMIC-CXR's labels were generated by an NLP tool reading
> FINDINGS and IMPRESSION. Feed those sections to a model and you are measuring
> whether it can re-read a sentence, not whether it can read a chest film.

## Where the labels come from

MIMIC-CXR-JPG ships two label files, `mimic-cxr-2.0.0-chexpert.csv.gz` and
`mimic-cxr-2.0.0-negbio.csv.gz`. Both were produced by running an automated
labeler over the **free-text radiology report** — not by a radiologist reviewing
the image.

The CheXpert labeler works by matching finding mentions and their negation or
uncertainty context, essentially always inside FINDINGS and IMPRESSION. So for a
study labelled `Pleural Effusion = 1`, the report almost certainly contains a
sentence like:

> FINDINGS: There is a small left pleural effusion with blunting of the
> costophrenic angle.

A model given that sentence does not need the film at all.

## What this looks like in practice

Ballpark figures on a MIMIC-CXR subset — run the ablation yourself rather than
quoting these:

| text mode | what the model sees | macro AUROC | what it measures |
|---|---|---|---|
| `findings` | the FINDINGS section | ~0.97–0.99 | can it re-read the labeler's input |
| `full` | the whole report | ~0.97–0.99 | same |
| `findings_masked` | FINDINGS, finding words redacted | ~0.80–0.90 | leftover phrasing cues |
| `indication` | pre-read sections only | ~0.75–0.85 | image + genuine clinical context |
| `none` | nothing | ~0.75–0.82 | image alone |

The gap between `findings` and `indication` is not a result about chest
radiography. It is a measurement of how circular the first setup is.

## What this project does

`text.mode` defaults to **`indication`**: only the sections written *before* the
radiologist reads the film.

```
EXAMINATION · INDICATION · HISTORY · CLINICAL HISTORY ·
CLINICAL INFORMATION · REASON FOR EXAM(INATION) · TECHNIQUE · COMPARISON
```

These carry real signal — "cirrhosis with ascites, evaluate for fluid" genuinely
raises the prior for an effusion — and it is signal a clinician has at the time
of interpretation. That is what makes a multimodal model defensible here: it is
using clinical context, not the answer key.

### The modes

| mode | content | leaky? |
|---|---|---|
| `indication` | pre-read sections only | no — the default |
| `findings` | FINDINGS only | **yes** |
| `impression` | IMPRESSION / CONCLUSION | **yes** |
| `full` | whole report | **yes** |
| `findings_masked` | FINDINGS with finding terms redacted | partly |
| `full_masked` | whole report with finding terms redacted | partly |
| `none` | empty string | no — image-only ablation |

Redaction (`*_masked`) replaces matches of `DISEASE_TERMS` in
`src/dvlhg/constants.py` with `[finding]`. It covers the four targets plus close
confounders (consolidation, pneumonia, opacity, pneumothorax, infiltrate),
because those co-occur strongly enough to leak by association. It is **not**
airtight — "blunting at the left base" survives redaction and still implies an
effusion — which is why it is labelled *partly* leaky rather than clean.

## Guardrails in the code

- `dvlhg prep` logs the text mode and its description, and emits a **warning**
  when a leaky mode is selected.
- `manifest/stats.json` records `text_mode` and `text_is_leaky`.
- `reports/report.md` prints a banner on any leaky run, stating the numbers are
  an upper bound.
- Every published figure and table therefore carries its own provenance.

## Two other leakage paths worth knowing about

**Patient overlap across splits.** Several studies per patient are common, and a
naive random split puts the same patient in train and test. MIMIC's official
split is patient-level; `prep` re-checks it and *refuses to continue* if any
patient straddles splits.

**Label-derived hyperedges.** The `proto_label` hyperedge family is built by
clustering training positives. Training nodes join their own cluster; every
other node joins by **feature distance to the centroid only**. A validation or
test node never contributes its label to the graph. See `docs/HYPERGRAPH.md`.

## What to write in the report

Report `indication` as the headline number. Report `findings` beside it,
explicitly labelled as the leaky upper bound, and explain the gap. That single
paragraph will do more for the project's credibility than half a point of AUROC.
